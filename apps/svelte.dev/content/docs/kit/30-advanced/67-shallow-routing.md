title: État de page & shallow routing
---

Lorsque vous naviguez sur une application SvelteKit, vous créez des _entrées d'historique_. Des
clics sur les boutons "Précédent" et "Suivant" vont parcourir cette liste d'entrées, en ré-exécutant
toute fonction `load` concernée, en remplaçant les composants de page, et en mettant à jour la
position de défilement lorsque nécessaire.

Parfois, il est pratique de créer des entrées d'historique _sans_ effectuer une navigation pleine et
entière. Nous appelons cela le _shallow routing_ ("routing creux").

Par exemple, vous pourriez vouloir afficher une modale de dialogue que l'utilisateur ou
l'utilisatrice pourrait fermer en naviguant vers la page précédente. Ceci est particulièrement utile
sur les appareils mobiles, où les gestes glissés sont souvent plus naturels que d'interagir
directement avec les éléments de l'interface graphique. Dans ces situations, une modale qui n'est
pas associée à une entrée d'historique de navigation peut être une source de frustration, puisque
les personnes pourraient faire un geste de glissement vers l'arrière en essayant de fermer la modale,
et finir par se retrouver sur une toute autre page.

SvelteKit rend ceci possible grâce à la fonction [`goto`]($app-navigation#goto), qui vous permet
d'associer un état avec une entrée d'historique sans effectuer de navigation, en utilisant l'option
`shallow: true` :

```svelte
<!--- file: +page.svelte --->
<script>
	import { goto } from '$app/navigation';
	import { page } from '$app/state';
	import Modal from './Modal.svelte';

	function showModal() {
		goto('', {
			state: { showModal: true },
			shallow: true
		});
	}
</script>

<button onclick={showModal}>ouvrir</button>

{#if page.state.showModal}
	<Modal close={() => history.back()} />
{/if}
```

Cet état est globalement accessible via l'[objet de page]($app-state#page) en tant que `page.state`.
Vous pouvez typer cet état de page en déclarant une interface [`App.PageState`](types#PageState) (en
général dans `src/app.d.ts`).

La modale peut être fermée en naviguant vers l'arrière (en désactivant `page.state.showModal`) ou en
interagissant avec elle de sorte à exécuter le callback `close`, ce qui déclenchera la navigation
arrière programmatiquement.

Vous pouvez mettre à jour le contenu de l'URL du navigateur lors d'une navigation creuse :

```js
import { goto } from '$app/navigation';
const state = { active: true };
// ---cut---
goto('/another/page', {
	state,
	shallow: true
});
```

> [!NOTE] Si l'utilisateur ou l'utilisatrice recharge la page, elle arrivera sur `/another/page`, et
> _non_ sur la page actuellement rendue — voir [Inconvénients](#Caveats).

Que vous choisissiez de mettre à jour l'URL visible ou non,
[`beforeNavigate`]($app-navigation#beforeNavigate), [`onNavigate`]($app-navigation#onNavigate) et
[`afterNavigate`]($app-navigation#afterNavigate) seront exécutées avec `navigation.type === 'goto'`
et `navigation.shallow === true`.

Une fois que la navigation creuse est active, `page.shallow` devient un objet `{ url, params, route
}` décrivant la page qui aurait été rendue si la personne avait navigué sur cette page (ce qui se
produirait si, par exemple, elle rechargeait la page). `page.url`, `page.params` et `page.route`
continuent de décrire la page actuellement rendue.

```svelte
<!--- file: +page.svelte --->
<script>
	import { goto } from '$app/navigation';
	import { page } from '$app/state';
</script>

<p>L'URL visible est {page.shallow?.url.href ?? page.url.href}</p>
<p>La page sur laquelle vous vous trouvez est {page.url.href}</p>

<button onclick={() => goto('/shallow', { shallow: true })}>effectuer une navigation creuse</button>
```

Un appel `goto` classique sans `shallow: true` ou un banal clic sur un lien permettre de sortir de
la navigation creuse.

Naviguer avec précédent ou suivant vers une entrée creuse restaure ses `page.state` et
`page.shallow`. La page rendue, et donc `page.url`, est toujours celle sur laquelle se trouvait
l'utilisateur ou l'utilisatrice lorsque `goto` a été appelée. Pour naviguer vers l'URL visible,
appelez `goto(page.shallow.url)` sans `shallow: true`.

> [!LEGACY]
> En SvelteKit 2, cette fonctionnalité était basée sur l'utilisation de `pushState` et
> `replaceState`, qui sont désormais dépréciées. Utilisez plutôt `goto` avec `shallow: true`, et
> utilsez l'option `replace` lorsque vous souhaiter remplacer l'entrée d'historique courante.

## Options de routing [!VO]Routing options

Par défaut, les exemples ci-dessus créent une nouvelle entrée de navigation dans la pile
d'historique. Si ce n'est pas ce que vous souhaitez, vous pouvez plutôt remplacer l'entrée de
navigation existante avec :

```js
import { goto } from '$app/navigation';
const url = new URL('https://example.com');
const state = { showModal: true };
// ---cut---
goto(url, {
	state,
	replace: true
});
```

Par défaut, l'état défini avec `goto` n’est pas restauré après un rechargement. Pour changer ce
comportement, utilisez `persistState` :

```js
import { goto } from '$app/navigation';
const url = new URL('https://example.com');
const state = { showModal: true };
// ---cut---
goto(url, {
	state,
	persistState: true
});
```

Les navigations creuses préservent par défaut la position de défilement courante ainsi que l'élément
ayant actuellement le focus. Vous pouvez désactiver ce comportement avec `reset: true` :

```js
import { goto } from '$app/navigation';
const url = new URL('https://example.com');
// ---cut---
goto(url, {
	shallow: true,
	reset: true
});
```

> [!NOTE]
> `page.state` est rempli uniquement après le chargement de JavaScript, ce qui peut provoquer des
> flashs dans l'interface graphique. Utilisez-le avec précaution.

## Charger des données pour une route [!VO]Loading data for a route

Lorsque vous utilisez le shallow routing, vous pourriez vouloir afficher une autre `+page.svelte` à
l'intérieur de la page courante. Par exemple, on peut imaginer un clic sur une vignette de photo qui
viendrait afficher le détail de la photo sans avoir à naviguer vers la page de la photo.

Pour que cela fonctionne, vous avez besoin de charger les données attendues par `+page.svelte`. Une
manière pratique de faire cela est d'utiliser la fonction
[`preloadData`]($app-navigation#preloadData) au sein du gestionnaire de `click` d'un élément `<a>`.
Si l'élément (ou un parent) utilise
[`data-sveltekit-preload-data`](link-options#data-sveltekit-preload-data), les données auront déjà
été demandées, et `preloadData` utilisera alors cette requête.

```svelte
<!--- file: src/routes/photos/+page.svelte --->
<script>
	import { preloadData, goto } from '$app/navigation';
	import { page } from '$app/state';
	import Modal from './Modal.svelte';
	import PhotoPage from './[id]/+page.svelte';

	let { data } = $props();
</script>

{#each data.thumbnails as thumbnail}
	<a
		href="/photos/{thumbnail.id}"
		onclick={async (e) => {
			if (innerWidth < 640        // ignore si l'écran est trop petit
				|| e.shiftKey             // ou si le lien est ouvert dans une autre fenêtre
				|| e.metaKey || e.ctrlKey // ou un nouvel onglet (mac: metaKey, win/linux: ctrlKey)
				// on devrait en théorie également considérer un clic avec le bouton de défilement de la
				// souris
			) return;

			// empêche la navigation
			e.preventDefault();

			const { href } = e.currentTarget;

			// ré-exécute les fonctions `load` (ou plutôt, récupère le résultat des fonctions `load` qui
			// sont déjà en cours à cause de `data-sveltekit-preload-data`)
			const result = await preloadData(href);

			if (result.type === 'loaded' && result.status === 200) {
				goto(href, { shallow: true, state: { selected: result.data } });
			} else {
				// quelque chose s'est mal passé ! on essaie de naviguer
				goto(href);
			}
		}}
	>
		<img alt={thumbnail.alt} src={thumbnail.src} />
	</a>
{/each}

{#if page.state.selected}
	<Modal onclose={() => history.back()}>
		<!-- fournit les données de page au composant +page.svelte
				 comme le ferait SvelteKit lors d'une navigation -->
		<PhotoPage data={page.state.selected} />
	</Modal>
{/if}
```

## Inconvénients [!VO]Caveats

Le routing creux nécessite JavaScript. Ayez-en conscience lors de son utilisation, et essayez de
prévoir des comportements alternatifs pertinents dans le cas où JavaScript ne serait pas disponible.

Le serveur n'a pas conscience de l'état d'historique. En conséquence, `page.state` est un objet vide
lors du rendu côté serveur, et un rechargement va effectuer une navigation vers l'URL
`page.shallow.url` précédente, si elle existe. En d'autres mots, si `page.shallow.url.pathname` vaut
`photos/123` avant le rechargement, `page.url.pathname` vaudra `/photos/123` après le rechargement,
et `page.shallow` vaudra `null`, indépendamment de l'option `persistState`. (Ceci ne vaut que pour
le chargement initial de la page, pour éviter un flash dans l'interface graphique lorsque
l'application cliente démarre.)
