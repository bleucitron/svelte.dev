## CSS

Une excellente manière d'utiliser des icônes est de les définir uniquement avec du CSS. Iconify
propose du support pour [beaucoup d'ensembles populaires
d'icônes](https://icon-sets.iconify.design/) pouvant être [inclus via
CSS](https://iconify.design/docs/usage/css/). Cette méthode peut également être utilisée avec des
frameworks CSS populaires en se servant des plugins [Tailwind CSS
plugin](https://iconify.design/docs/usage/css/tailwind/) ou [UnoCSS
plugin](https://iconify.design/docs/usage/css/unocss/). À la différence de librairies basées sur
des composants Svelte, cette méthode ne nécessite pas que chaque icône soit importée dans votre
fichier `.svelte`.

## Svelte

Il y a beaucoup de [librairies d'icônes pour
Svelte](https://www.sveltesociety.dev/packages?category=icons). Lorsque vous choisissez une
librairie d'icônes, il est recommandé d'éviter que celles-ci fournissent un fichier `.svelte` par
icône, car ces librairies peut avoir des milliers de fichiers `.svelte` qui ralentissent beaucoup le
[processus d'optimisation de dépendances de Vite](https://vite.dev/guide/dep-pre-bundling.html).
Ceci peut devenir particulièrement pathologique si les icônes sont importées à la fois via des
imports "parapluie" et par des imports "subpaths", [comme décrit dans la FÀQ de
`vite-plugin-svelte`](https://github.com/sveltejs/vite-plugin-svelte/blob/main/docs/faq.md#what-is-going-on-with-vite-and-pre-bundling-dependencies).
