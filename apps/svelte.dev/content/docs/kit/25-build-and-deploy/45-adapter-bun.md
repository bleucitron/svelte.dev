L'adaptateur [`adapter-bun`](https://github.com/sveltejs/kit/tree/main/packages/adapter-bun) compile
une application SvelteKit en un serveur [Bun](https://bun.com/) autonome. Le serveur généré utilise
`Bun.serve` pour les requêtes et des réponses `Bun.file` pour les assets client, les sorties
pré-rendues et les fichiers lus avec [`read`](https://svelte.dev/docs/kit/$app-server#read) importé
depuis `$app/server`.

> [!NOTE] Bun 1.4 ou plus récent est requis.

## Usage

Installez l'adaptateur :

```sh
bun add -D @sveltejs/adapter-bun
```

Configurez-le avec `vite.config.js` :

```js
// @errors: 2307 2554
/// file: vite.config.js
import adapter from '@sveltejs/adapter-bun';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
	plugins: [
		sveltekit({
			adapter: adapter()
		})
	]
});
```

L'adaptateur appelle l'API de compilation de Bun, ce qui implique que le build de production doit
être exécuté avec Bun. L'option `--bun` écrase le shebang Node.js de Vite :

```sh
bun run --bun build
```

Le build par défaut est écrit dans le dossier `build`. Démarrez-le avec :

```sh
bun ./build
```

Vous aurez besoin du dossier généré, du fichier `package.json`, et des dépendances de production de
vos `node_modules` pour exécuter votre application. Les dépendances de production peuvent être
générées en copiant les fichiers `package.json` et `bun.lock`, puis en lançant `bun install
--production --frozen-lockfile` (vous pouvez ignorer cette étape si votre application n'a pas de
dépendance). Les dépendances de développement sont empaquetées dans votre application. Pour
contrôler si un paquet donné est empaqueté ou externalisé, placez-le dans les `devDependencies` ou
`dependencies`, respectivement, de votre fichier `package.json`.

Les assets client et les sorties pré-rendues sont enregistrées comme des routes Bun natives. Seules
les requêtes `GET` et `HEAD` sont servies par ces routes ; les autres méthodes continuent vers
SvelteKit. Chaque asset port un ETag calculé lors de la compilation, afin que les requêtes
conditionnelles soient revalidées avec une réponse `304` vide. Bun fournit les types MIME, les
plages d'octets pour les fichiers portés par le système de fichiers, et le streaming sans mettre
chaque asset en mémoire tampon. Les fichiers dans le dossier `immutable` de SvelteKit reçoivent
`Cache-Control: public,max-age=31536000,immutable`.

> [!NOTE] Bun traite un `*` dans un chemin de route comme un joker. L'adaptateur rejette les
> fichiers client et les fichiers pré-rendus contenant un `*` litéral ; renommez ces fichiers avant
> la compilation.

## Options

```js
// @errors: 2307 2554
/// file: vite.config.js
import adapter from '@sveltejs/adapter-bun';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
	plugins: [
		sveltekit({
			adapter: adapter({
				out: 'build',
				envPrefix: '',
				serverOptions: {
					idleTimeout: 30
				}
			})
		})
	]
});
```

### out

Le dossier de sortie. Vaut par défaut `build`.

### precompress

Définissez `precompress: true` pour générer des variants `.br` et `.gz` des assets client et
pré-rendus lors de la compilation. Les routes générées négocient `Accept-Encoding` pour chaque
requête, préférant brotli plutôt que gzip, et chaque variant porte son propre ETag. Cette option est
ignorée lorsque `buildOptions.compile` est défini, car les assets embarqués sont importés par chemin
d'identité.

### envPrefix

Un préfixe pour chaque variable d'environnement de déploiement documentée ci-dessous. Cette option
permet d'éviter les conflits de noms avec des variables d'environnement gérées par votre plate-forme
de déploiement :

```js
// @errors: 2307
import adapter from '@sveltejs/adapter-bun';
// ---cut---
adapter({ envPrefix: 'MY_APP_' });
```

```sh
MY_APP_HOST=127.0.0.1 MY_APP_PORT=4000 bun ./build
```

Lorsqu'un préfixe est configuré, le serveur échoue au démarrage s'il rencontre une variable
d'environnement inconnue ayant ce préfixe. Cela permet de détecter les collisions de noms et les
erreurs de typographie.

### serverOptions

Des valeurs par défaut passées à `Bun.serve`, sérialisables en JSON. Les propriétés supportées sont
les suivantes :

- `hostname`
- `port`
- `unix`
- `reusePort`
- `ipv6Only`
- `idleTimeout`
- `maxRequestBodySize`
- `development`

Les variables d'environnement sont prioritaires sur ces valeurs par défaut. Un socket Unix configuré
est prioritaire sur `hostname`, `port`, `reusePort`, et `ipv6Only`.

Le serveur généré a le contrôle de `fetch` et `routes`. Il n'expose pas `websocket`, `error`, les
configurations TLS, HTTP/3 ou HTTP/1 via `serverOptions`. Utilisez une intégration Bun personnalisée
si votre application nécessite ces options de `Bun.serve`.

### buildOptions

`buildOptions` configure l'appel `Bun.build` qui tranforme le serveur en un exécutable, cette option
ne s'applique donc que lorsque l'option `compile` est définie. L'adaptateur accepte `sourcemap`,
`minify`, `bytecode`, `banner`, `footer`, `drop`, `features`, `optimizeImports`, `external`, et
`compile`. Le point d'entrée, le dossier cible, la `target` racine, et le `format` du module sont
conservés. Les sourcemaps valent par défaut `external` ; mettez `sourcemap: none` pour les
désactiver.

#### Exécutables compilés [!VO]Compiled executables

Définissez `compile: true` pour générer un exécutable unique dans `<out>/server` :

```js
// @errors: 2307
import adapter from '@sveltejs/adapter-bun';
// ---cut---
adapter({
	buildOptions: {
		compile: true
	}
});
```

Compilez-le et exécutez-le sans aucun environnment Bun installé indépendamment :

```sh
bun run --bun build
./build/server
```

L'exécutable embarque le code serveur, les assets client, les sorties pré-rendues, et l'environnment
d'exécution Bun. `compile` peut également être une chaîne de caractères cible de Bun, qui garde le
nom de fichier `server` par défaut, ou un objet d'options. Pour changer le nom de l'exécutable ou
effectuer une compilation croisée, fournissez un objet d'option :

```js
// @errors: 2307
import adapter from '@sveltejs/adapter-bun';
// ---cut---
adapter({
	out: 'dist',
	buildOptions: {
		compile: {
			outfile: 'application',
			target: 'bun-linux-x64'
		},
		minify: true,
		bytecode: true,
		sourcemap: 'linked'
	}
});
```

Le résultat dans cet exemple est `dist/application`. Les cibles des plateformes, les dépendences
natives et autres limitations suivent les [règles de compilation des exécutables
Bun](https://bun.com/docs/bundler/executables).

Les exécutables compilent les dépendances de production, puisqu'il n'y a pas de `node_modules`
depuis lequel les résoudre. Pour plutôt résoudre un paquet depuis `node_modules` au moment de
l'exécution, listez-le dans `external` et définissez `compile: { autoloadPackageJson: true }`. Les
paquets qui lisent des fichiers relatifs à leur propre emplacement, comme `jsdom`, fonctionnent
uniquement de cette façon.

## Variables d'environnement [!VO]Environment variables

Bun charge les fichiers `.env` automatiquement. Si `envPrefix` est défini, ajoutez ce préfixe à
chaque nom dans cette section.

### Gestionnaire TCP [!VO]Listener

`HOST` et `PORT` configurent le gestionnaire TCP. Si aucune de ces deux valeurs n'est définie, ni
une valeur définie dans `serverOptions`, le serveur écoute sur le port `3000`.

```sh
HOST=127.0.0.1 PORT=4000 bun ./build
```

`SOCKET_PATH` sélectionne plutôt un socket de domaine Unix. Lorsqu'il est définit, les options
spécifiques à TCP sont ignorées :

```sh
SOCKET_PATH=/tmp/sveltekit.sock bun ./build
```

`REUSE_PORT` active l'option `reusePort` de Bun et `IPV6_ONLY` active `ipv6Only`. Les variables
booléennes acceptent `1`, `true`, `yes` et `on`, ou `0`, `false`, `no` et `off`, en ignorant la
casse.

### Limites et diagnostic des requêtes [!VO]Request limits and diagnostics

`BODY_SIZE_LIMIT` contrôle l'option `maxRequestBodySize` de `Bun.serve`. Elle vaut par défaut
`512K`. La valeur doit correspondre à un nombre entier d'octets et peut utiliser un suffixe `K`,
`M`, `G` ignorant la casse tel que `768K` ou `1.5M`. `Infinity` désactive cette limite.

`CONNECTION_IDLE_TIMEOUT` définit le délai d'inactivité de chaque requête, en secondes. Cette valeur
doit être un entier entre `0` et `255` ; `0` désactive le délai. Le gestionnaire généré désactive le
délai pour les réponses dont le type du contenu commence par `text/event-stream`, et y ajoute
également `X-AccelBuffering: no`. Cette option n'est pas nommée `IDLE_TIMEOUT` délibéremment, qui
a une autre signification pour l'adaptateur `adapter-node` (éteint le serveur après N secondes sans
requête).

`DEVELOPMENT` active les pages d'erreur du mode de développement de Bun. Il vaut par défaut `false`
pour le serveur généré.

### Origine publique derrière un proxy [!VO]Public origin behind a proxy

Si [`paths.origin`](configuration#paths) est configurée, cette valeur est l'origine de confiance
pour chaque requête. Sinon, l'adaptateur extrait l'hôte depuis l'en-tête `Host` et suppose que le
protocole est `https`, puisque les déploiements de production stoppent le TLS en amont. Configurez
`paths.origin` ou `PROTOCOL_HEADER` si cette supposition est fausse, par exemple lorsque vous servez
du HTTP brut en direct.

Derrière un proxy de confiance, les en-têtes de noms `PROTOCOL_HEADER`, `HOST_HEADER`, et
`PORT_HEADER` contenant un protocole, un hôte et un port publics :

```sh
PROTOCOL_HEADER=x-forwarded-proto \
HOST_HEADER=x-forwarded-host \
PORT_HEADER=x-forwarded-port \
bun ./build
```

L'en-tête de protocole doit contenir `http` ou `https`, sans virgule. L'en-tête de port doit
contenir un nombre. Les valeurs invalides produisent une réponse `400 Bad Request`. Une en-tête qui
serait présente mais vide est ignorée en faveur de sa valeur par défaut.

> [!CAUTION] Ne faites confiance aux en-têtes relayées que lorsque les requêtes ne peuvent atteindre
> votre serveur qu'au travers d'un proxy que vous contrôlez. Un client direct peut manipuler ces
> en-têtes.

### Adresses client derrière un proxy [!VO]Client addresses behind a proxy

[`event.getClientAddress()`](https://svelte.dev/docs/kit/@sveltejs-kit#RequestEvent) utilise
`server.requestIP(request).address` par défaut. Donnez à `ADDRESS_HEADER` le nom d'une en-tête d'un
proxy de confiance lorsque le pair direct est un proxy :

```sh
ADDRESS_HEADER=true-client-ip bun ./build
```

Pour `x-forwarded-for`, définissez aussi `XFF_DEPTH` comme le nombre de proxys de confiance. La
profondeur par défaut est `1`, et l'adaptateur choisit depuis le côté droit de la liste séparée par
des virgules, afin que les entrées fournies sur le côté gauche par le client ne puissent pas changer
le résultat auquel vous faites confiance :

```sh
ADDRESS_HEADER=x-forwarded-for XFF_DEPTH=2 bun ./build
```

`XFF_DEPTH` doit être un entier valant au moins `1`. `getClientAddress()` jette une erreur si
l'en-tête configurée est absente ou contient moins d'adresses que la profondeur configurée.

## API de plateforme [!VO]Platform API

La propritété `platform` de l'évènement de requête expose l'instance du serveur Bun :

```js
/** @type {import('./$types').RequestHandler} */
export function GET({ getClientAddress, platform }) {
	return Response.json({
		address: getClientAddress(),
		serverId: platform.server.id,
		pendingRequests: platform.server.pendingRequests,
		pendingWebSockets: platform.server.pendingWebSockets
	});
}
```

## Arrêt gracieux [!VO]Graceful shutdown

Lors d'un signal `SIGINT` ou d'un `SIGTERM`, le serveur généré appelle `server.stop()`. Bun arrête
d'accepter des nouvelles connexions et l'adaptateur attend la fin du traitement des requêtes en
cours avant d'émettre un évènement de processus `sveltekit:shutdown` avec le nom du signal :

```js
process.on('sveltekit:shutdown', async (reason) => {
	await jobs.stop();
	await db.close();
});
```

Les connexions qui sont toujours ouvertes après un délai de `SHUTDOWN_TIMEOUT` secondes sont fermées
de force, ce qui implique que les connexions en pause telles que les streams d'évènements ouverts ne
peuvent pas retarder l'extinction indéfiniment. La valeur doit être un entier non négatif et vaut
par défaut `30`.

Envoyer un deuxième signal d'extinction force la sortie du process avec un statut `1`.
